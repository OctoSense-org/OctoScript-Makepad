# L0 conformance: what a reference card must evaluate to.
#
# There are two evaluators for the same contract. `splash-render` walks the DSL
# with the makepad-splash VM; octos-one walks it with its own, because taking
# `splash-render` there fails the lockfile on `makepad-error-log v1.0.0` existing
# at two paths. The model (`splash-node`) is shared; only the walk is duplicated.
#
# A duplicated walk drifts unless something checks it. Neither repository can run
# the other's evaluator — that is the whole reason there are two — so the check
# is this file: a number both test suites read and compare their own result to.
#
# WHY NOT HARDCODE IT. An earlier version of octos-one's test carried these
# counts as literals copied from a note, and they were three commits stale the
# first time they were run: they predated the tap wrappers, which add a node per
# declared tap. The test reported a divergence between the two evaluators that
# did not exist. A shared number cannot do that — when the tree legitimately
# changes, both suites fail together and one edit here fixes both.
#
# The counts are for the fixtures in Splash/crates/splash-ui-l0/tests/fixtures,
# realized against the data in each suite's own helper, lowered by `kit::lower`,
# concatenated with `_kit.splash`, and evaluated.
#
# weather dropped from 64 to 60 when the five data visualisations stopped being
# markers. A marker was a card wrapping a label — two nodes — and a real widget
# is one. Both suites failed together and this line fixed both, which is the
# workflow this file exists for.
#
#   card     nodes
news         41
stock        21
weather      71

# CHANGING A NUMBER HERE. weather went 60 → 66 when the card gained a `Satellite`
# cloud pane and a `Row` that stops filling, and swapped its visibility tile for
# precipitation. Six nodes is the honest cost of those. The number was raised only
# after BOTH evaluators independently reported 66 — they agreed with each other and
# disagreed with this file, which is the one direction that means the fixture moved
# rather than a walk drifting. Never raise it to whatever one evaluator says.
#
# weather went 66 → 72 when the card gained the saved-cities strip (§5.12): the
# strip's panel and its tappable "add a city" row evaluate even in the test data's
# empty state — nothing saved, editor closed. Same workflow as the line above:
# both evaluators reported 72 independently, then this line moved.
#
# stock went 12 → 15 when the card gained its §5.12 personal layer: a ☆ chip on
# each of the three test-data mover rows saves the ticker (the watchlist strip
# itself and the news card's reading list evaluate to nothing in the test data —
# empty store, feed screen — so they cost no nodes here). Both evaluators
# reported 15 independently before this line moved.
#
# stock 15 → 16: the mover row's ☆ chip moved OUT of the tappable row to sit
# beside a filling inner tap row — a row's transparent hit target covers its
# whole content, so a chip inside one fires the row's event (measured on the
# 6T with weather's × chip; same class, same fix). One wrapper node per test
# mover. Both evaluators reported 16 independently before this line moved.
#
# news 27 -> 41: the TOPICS block — a header, four suggestion chips (each a
# tap), and per-followed-topic rows in the sibling-chip shape. Store-backed
# rows are empty in the fixture, so the delta is the static block only. Both
# evaluators reported 41 independently before this line moved.
#
# weather 72 -> 71: the add-a-city affordance moved from a full-width row
# under the saved strip into a + chip in the title bar (top-right corner,
# asked for by hand on device), net one node fewer. Both evaluators
# reported 71 independently before this line moved.
#
# stock 16 -> 21: the add flow's always-present header bar (WATCHLIST caption
# + the top-right + chip) joins the list view; the editor and the red manage-
# mode Remove are behind guards the fixture leaves closed. Both evaluators
# reported 21 independently before this line moved.
